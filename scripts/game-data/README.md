# Game data from Data Dragon and professional play

Two pipelines put real League of Legends data into committed files under `assets/simulation/`. The live match reads
them; nothing downloads data at match start.

| Command | Writes | Source |
|---------|--------|--------|
| `node scripts/game-data/ddragon.mjs` | `items.v1.json`, `champion-kits.v1.json`, icons under `public/` | Riot Data Dragon (`ddragon.leagueoflegends.com`) |
| `node scripts/game-data/pro-builds.mjs` | `champion-builds.v1.json` | Leaguepedia `ScoreboardPlayers` (CC BY-SA 3.0) |

Pure transformation lives in `lib/*.mjs` (typed by `lib/*.d.mts`) and is tested in `src/lib/gameData/`. The committed
Data Dragon files are checked by `src/lib/gameData/gameDataFiles.test.ts`.

## Data Dragon: items, champion kits, icons

```bash
node scripts/game-data/ddragon.mjs                          # newest patch in api/versions.json
node scripts/game-data/ddragon.mjs --version 16.22.1        # a given patch
node scripts/game-data/ddragon.mjs --version 16.22.1 --offline   # rebuild from the cache, no network
```

- Requests: read-only GETs to `ddragon.leagueoflegends.com`, one at a time, 1 s apart, generic client name, redirects
  refused, capped by `--max-requests`. Responses are parsed as JSON (images must carry the PNG signature) and never
  executed.
- Cache: `src-tauri/target/olm-scratch/ddragon-cache` (gitignored). A rerun reuses it; the header date is the day the
  item file was first downloaded, so an offline rebuild gives byte-identical files.
- `items.v1.json` keeps what a player can buy on Summoner's Rift, components and boots included. Filter, in order:
  `maps.11` true; id below 100000 (higher ids are mode copies); not `hideFromAll`; no `requiredChampion`; no
  `requiredAlly`; `gold.purchasable` true and `inStore` not false; one entry per name (lowest id). Counts per reason are
  in the file's `filter` block. `key` follows the icon file style (`infinity_edge`). `stats` is Data Dragon's object;
  `statLines` is the description's stat block (it has ability haste, which `stats` lacks). Flags: `boots` (Boots tag or
  built from boots), `starter` (Lane/Jungle shop item up to 500 gold with at most one upgrade), `consumable`,
  `trinket`, `support` (support quest line). `retiredKeys` lists item icon files that existed before this pipeline and
  whose item is no longer sold.
- `champion-kits.v1.json` has every Data Dragon champion keyed by Data Dragon id, with `inCatalogue` marking those in
  `assets/simulation/champion-list.json` (the catalogue is not regenerated by this script). Per champion: base stats
  and growth as given, attack range, resource, tags, passive, four abilities (cooldowns, costs, range, description with
  markup stripped) and `ultimate`: `{ archetype, icon }`. The archetype comes from `classifyUltimateArchetype`, the
  keyword classifier the live view used at match start, applied to the raw tooltip.
- Icons: new files only; an existing file is never overwritten. Items go to `public/lol-item-icons/<key>.png`, the
  five summoner spells to `public/lol-summoner-icons/`, ultimates to `public/lol-ultimate-icons/`.

## Leaguepedia: builds and presence

```bash
node scripts/game-data/pro-builds.mjs --probe --since 2026-11-01 --until 2026-11-12   # one row: confirms the fields
node scripts/game-data/pro-builds.mjs --since 2025-11-12 --until 2026-11-12           # the pull (about 300 pages)
node scripts/game-data/pro-builds.mjs --since 2025-11-12 --until 2026-11-12 --offline # rebuild from the cache
```

- Scope: the same as `scripts/champions/pro-matchups.mjs`: every game of Cargo `ScoreboardPlayers` (joined to
  `ScoreboardGames` for the patch) inside the date window, no league filter. Use the most recent twelve months.
- Client: the world tooling client (generic User-Agent, 4 s throttle, maxlag, bounded retries, on-disk cache in
  `src-tauri/target/olm-scratch/lp-builds-cache`). Anonymous by default; `--login` uses the bot-password helper of the other scripts
  (see `scripts/champions/README.md`, "Logging in"). When Leaguepedia answers `ratelimited` the run fails after its
  retries; it never falls back to another host.
- Aggregation (per champion and role): games, wins, games with item data, how often each finished item was in the
  final build, the boots, and the most frequent three-item cores. Item names are mapped to `items.v1.json` keys;
  names that do not map are listed in `unmappedItems`. Finished means a complete recipe that is not boots, a
  consumable, a trinket, a starter or the support quest line.
- Recommended build: the most frequent boots plus the five most frequent finished items, most frequent first (ties by
  key). A pair with fewer than `minGames` games with item data (default 20: a 50% item then has a standard error of
  about 11 points, and it is the sample the lane matchup script requires) gets `build: null, fallback: "class"` and its
  champion's first tag as `class`; its games and wins still count as presence.
- The header records the leagues, window, first and last game, patches with their game counts, games, minimum sample
  and the date of the pull.
